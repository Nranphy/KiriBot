# KiriBot 总体架构与目录结构

## 文档定位

本文说明 Manager、Gateway 与 Instance 的运行边界、通信方式，以及这些职责在仓库中的位置。产品定位与用户视角的整体架构图见[项目背景](01.project-overview.md#项目架构)。

## 运行架构

Manager 是常驻主应用，Controller、Gateway 和管理服务运行在同一进程内。Instance 在独立进程中运行，业务插件由 Instance 的机器人框架加载。普通用户通过聊天平台使用机器人，管理员通过 Bot 指令或 HTTP API 管理同一套应用。

| 路径 | 组件如何协作 |
| --- | --- |
| 用户消息与回复 | 外部协议端把平台事件交给 Gateway，Gateway 将事件转发给已连接的客户端。Instance 处理业务，并通过 Gateway 调用平台 API 发送回复。 |
| 管理操作 | 聊天中的管理指令经 Gateway 到达 Controller，HTTP 管理请求直接到达 Controller。两个入口调用相同的管理服务。Instance 停止后，管理员仍可通过 Manager 管理 Instance。 |

### Gateway 与协议接入

外部协议端和 Instance 均连接 Manager 内的 Gateway。Controller 的 Bot 适配器也作为内部客户端接入。Gateway 用连接名区分外部通道，用客户端标识区分内部调用方，保留各协议的事件格式与请求语义。

| 协议 | 外部接入 | 内部通信 |
| --- | --- | --- |
| OneBot v11 | 支持 Universal WebSocket 正向与反向连接。 | Controller 或 Instance 连接内部 WebSocket。Gateway 转发事件，并将 Action 响应送回发起请求的客户端。 |
| Satori | Gateway 主动连接外部服务的事件流。 | 内部客户端订阅事件，并通过 Gateway 代理调用 Satori HTTP API。 |

外部连接配置需声明聊天平台，当前支持 QQ。Manager 启动时生成内部令牌，供 Controller 和受管 Instance 连接 Gateway。外部连接中断时，Gateway 关闭该通道对应的内部连接，由客户端适配器重连；离线期间的事件不会补发。

### 管理服务与 Instance

Manager 使用 `instances` 对象的键名作为 Instance ID 和工作目录名。例如，键名 `music` 对应 `instances/music/`。管理员先将模版手动复制到该目录，再在 `config/instances.json` 登记 Instance、启动命令和外部连接名。

Manager 启动时仅读取 Instance 配置，对标记为 `auto_start` 的 Instance 执行启动命令。缺少 Instance 配置时，Instance 列表为空；已登记的目录缺失时报告配置错误。模版目录不会触发 Instance 初始化。

Gateway 从平台事件中提取用户和群聊信息，通过队列异步写入数据库，使存储故障不阻断消息转发。用户由内部 ID 标识，平台身份按平台名与平台用户 ID 关联。权限服务优先检查配置中的黑名单和超级管理员，再按群聊范围、有效期及权限优先级计算数据库授权。

Bot 管理指令要求调用者的最终权限为 `SUPERADMIN`。现有 HTTP 管理入口尚未接入身份认证，部分路由仍使用 GET、PUT、DELETE 或路径参数。项目自定义 HTTP API 的设计以[接口风格](02.conventions.md#接口风格)为准；Gateway 对外代理的平台 API 遵循对应协议。

## 目录结构

下表列出当前仓库的主要目录。新增文件时先确定由哪个进程使用，再按职责放入对应模块。

| 位置 | 存放内容 |
| --- | --- |
| `src/kiribot/` | Manager 应用包，`__main__.py` 为进程入口。仓库根目录的 `pyproject.toml` 和 `uv.lock` 管理其依赖。 |
| `config/` | Gateway 连接与 Instance 的配置示例。Manager 的环境变量示例位于根目录 `.env.example`。 |
| `templates/nonebot2/` | NoneBot2 模版，维护源码、依赖和测试。 |
| `instances/` | 本机部署的 Instance 工作目录，由管理员准备并独立维护。 |
| `tests/manager/` | Manager 的管理入口、服务及协议通信测试。 |
| `docs/` | 项目背景、开发约定和架构文档。 |

### Manager 模块归属

Manager 在 `src/kiribot/` 下先按层组织，各层内部再按业务领域拆分。管理请求通常由 Controller 调用 Service，再由 Service 调用 Client 访问数据库或子进程。

| 位置（相对应用包） | 职责与放置约定 |
| --- | --- |
| `controller/` | `app.py` 组装应用并管理生命周期，`loader.py` 在 NoneBot 初始化后加载管理模块。`admin/` 按领域组织 HTTP 管理接口、Bot 指令及对外请求响应模型。`gateway.py` 挂载协议端点。 |
| `services/` | 按领域组织业务规则。`instances/` 负责 Instance 生命周期，`users/` 负责身份记录，`permissions/` 负责授权与有效权限计算。 |
| `services/gateway/` | 协调外部会话、内部订阅和传输。OneBot v11 与 Satori 的会话处理、协议路由和事件提取分别放在 `onebot11/`、`satori/` 中。 |
| `clients/` | 封装可供服务复用的底层访问。`database.py` 维护数据库连接和 ORM 模型，`process.py` 封装子进程操作。协议专用客户端随对应 Gateway 协议实现维护。 |
| `models/` | 按领域组织配置与内部业务模型，包括 Instance 状态、用户身份及权限类型。 |
| `infra/` | 维护应用运行所需的配置加载、日志和浏览器环境。 |

### 模版与 Instance 入口

NoneBot2 模版的应用代码位于 `templates/nonebot2/src/`。其中 `main.py` 是 Instance 复制后的启动入口，`connection.py` 将 Manager 注入的连接信息交给适配器，`plugins/` 存放业务插件。模版测试位于 `templates/nonebot2/tests/`。
