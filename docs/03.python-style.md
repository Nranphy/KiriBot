# KiriBot Python 代码风格

## 文档定位

本文约定 Manager 和 Python Worker 的命名、类型、文档字符串及资源管理方式。跨语言的开发约定见[代码与文档规范](02.conventions.md)，模块归属见[架构与目录结构](04.architecture.md#目录结构)。

## 命名与模块

模块、函数、方法和变量使用 `snake_case`，类与数据模型使用 `PascalCase`，常量使用 `UPPER_SNAKE_CASE`。名称应说明业务含义，例如用 `instance_id` 和 `connection_name` 区分实例与协议连接。

导入按标准库、第三方库、项目内部模块分组，组间留空行。包的 `__init__.py` 可导出稳定入口。数据库连接、后台任务等资源由应用生命周期创建和关闭，避免导入模块就启动服务。

## 类型与数据模型

公共函数、接口处理函数、服务方法和客户端方法应标注参数及返回类型，类属性也应声明类型。使用 `list[str]`、`str | None` 等与项目 Python 版本兼容的语法。已知结构应使用具体类型。

| 数据用途 | 建模约定 |
| --- | --- |
| 外部请求、响应与配置 | 使用 Pydantic 表达字段类型和约束，在接收输入时完成校验。 |
| 内部业务数据 | 按业务含义命名，简单记录可使用 `dataclass`。只有多个模块依赖同一含义和约束时，才提取共享模型。 |
| 数据库记录 | ORM 模型由数据访问层维护，返回给调用方时按业务或接口契约转换。 |

## 异步、事务与错误处理

- 数据库、HTTP 和 WebSocket 等 I/O 在异步处理流程中使用异步接口。耗时的同步调用交给线程或独立进程执行。
- 连接、会话和后台任务由创建它们的组件负责关闭。外部调用设置合适的超时，初始化中途失败时也要释放已取得的资源。
- 涉及多次写入的业务操作由服务统一划定事务边界。需要并发保证的唯一性或状态变更，使用数据库约束或原子操作。
- 用具体异常表达失败原因，由 HTTP 或 Bot 入口转换为相应结果。受保护的操作应在可信边界校验权限，日志和错误信息应排除令牌等敏感数据。

## 文档字符串

关键模块、类、函数和方法使用中文文档字符串，说明职责以及调用者需要了解的约束。单行概括与三引号放在同一行，末尾省略句号。多行说明的起始三引号单独成行，按需说明参数、返回值、异常和资源归属。

## 开发检查

在对应 Python 项目的根目录执行检查。Manager 使用仓库根目录，NoneBot2 Worker 使用 `workers/nonebot2/`。两个项目分别维护自己的依赖、工具配置和测试。

| 目的 | 命令 |
| --- | --- |
| 按锁文件准备环境 | `uv sync --locked` |
| 检查代码与格式 | `uv run ruff check .`、`uv run ruff format --check .` |
| 检查类型 | `uv run pyright` |
| 验证行为 | `uv run pytest`，或指定受影响的测试路径 |

异步和数据访问代码除成功路径外，还应按改动范围验证超时、资源释放、事务回滚或权限边界。
